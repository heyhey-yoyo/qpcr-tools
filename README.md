# qPCR 孔板模板设计与 ΔΔCt 分析工具

一个纯前端静态网页：qPCR（实时荧光定量 PCR）孔板模板设计与 ΔCt / ΔΔCt 相对表达分析工具。数据完全在浏览器本地计算，无需后端、无需构建、无需安装。

## 主要功能

**实验配置**

- 分组管理：芯片式 UI，支持添加、改名、删除、选择比较基准组（一个孔板可设多个校准组）
- 目标基因管理：芯片式 UI，支持添加、改名、删除，数量随孔板容量自动限制
- 内参基因：芯片式 UI，支持改名
- 生物学重复数：1–24，独立设置
- 技术复孔数：1–6，全局统一

**孔板模板设计**

- 96 孔板（8×12）与 384 孔板（16×24）切换
- 横向/纵向点板，可选起始孔位置；孔间默认间距充足（96 孔板 10px，384 孔板 8px）
- 区块间空孔设置（0–2）
- 将预设载入孔板：按当前配置一键生成完整模板，覆盖现有区块
- 功能演示：一键载入 4 组 × 3 目标基因 × 2 生物学重复的示例模板
- 手动添加/删除/上下移动单个区块
- 区块「另起一行」开关，控制排版换行
- 孔位排布可视化预览：同一区块的技术重复用浅色框圈出，组别用颜色区分

**模板导入/导出**

- 导出当前模板为 JSON 文件（含实验配置、复孔数、完整区块列表）
- 从 JSON 文件导入模板，自动恢复实验配置，导入后孔板预览与 Ct 数据表同步刷新

**Ct 数据录入**

- Ct 数据表为只读结构（无删除按钮），样本/组别/基因随第二步区块表实时同步
- 一键读取剪贴板中的罗氏单列 Ct / Cp / Cq 数据，严格按孔位顺序填入
- 手动粘贴后点击「填入当前数据表」作为降级路径
- 支持 Ct、Cq、Cp 表头，兼容 Undetermined、No Ct、空行等缺失值
- Ct 值即时校验（0 < Ct ≤ 50），无效值红色边框标记
- 随机 Ct 测试：自动生成模拟数据用于功能验证

**数据分析**

- 两种分析模式：相对表达量（2^-ΔΔCt）和归一化表达量（2^-ΔCt）
- ΔCt = 目标基因 Ct − 内参基因 Ct
- ΔΔCt = ΔCt(样本) − 对照组同基因平均 ΔCt
- 相对表达量 = 2^−ΔΔCt，含上下限（由技术重复 SEM 传播）
- 技术重复质控（Ct 最大差值阈值检测）
- 对照组生物学重复 SEM（≥2 个生物学样本时计算；单样本时显示为空）
- 单孔记录给出点估计但不画误差棒，标记「单孔」

**可视化**

- 个体样本柱状图：每样本一根柱，含误差棒（技术重复 SEM）
- 分组汇总图（多目标基因时）：按分组聚类，基因作为簇内彩色柱，含图例
- 长名称自动截断，悬停显示全名

**导出与持久化**

- 点板清单 CSV 导出
- 分析结果 CSV 导出（带 BOM，兼容 Excel）
- 模板 JSON 导出/导入
- 复制结果到剪贴板
- 全部状态自动保存到浏览器 localStorage（键 `qpcr-demo-v7`）
- 恢复默认：一键清除所有数据并重置配置

## 界面风格

工具主体采用 `ydchen-portfolio` 的米白、浅灰与赤陶色视觉系统，使用衬线标题和扁平化分析卡片；页眉仍保持原有 `YDchen Tools` 结构与样式。

工具主体正文采用 16px 基线，操作标签不小于 12px；384 孔板内的紧凑注释可保持较小字号，但必须可辨认。桌面与手机端允许孔板或表格容器内部横向滚动，不得造成页面整体溢出。

本项目为 Tools 工具类。页眉桌面 72px、手机（≤640px）64px；YDchen 为衬线 20px/600，Tools 为无衬线 20px/300，手机字标 18px；标题 18px/600、手机 16px；分隔线 36px/32px，品牌、分隔线与标题间距 16px/12px。

页眉内容区最大宽度 1280px（含两侧各 16px 内边距），整体居中；品牌和标题靠左，操作区靠右，窄屏换行后仍保持该对齐。品牌页眉在文档顶部正常排布，随页面滚走，不固定或吸顶；表格内部表头、侧边工具和手机底部导航可按功能保留。

正文采用统一系统无衬线字体，默认 16px / 1.6；标题采用 Georgia、Times New Roman、Songti SC、STSong 衬线族。数字与代码可使用 SFMono-Regular、Consolas、Liberation Mono、Microsoft YaHei 等宽族。按钮和输入通常 15px，辅助文字 12–14px，密集科学数据允许有理由的局部调整。页面底色 #f3eee5、正文 #24221f、赤陶强调 #a94f31，柔和底色上的强调文字 #823a25；科学分类色、热图、作品主题与状态色保留必要区分度。

## 数据与隐私

- 所有数据仅在浏览器本地处理，不会上传至任何服务器
- 状态仅存储在 `localStorage`，可随时清除
- 无任何网络请求或远程依赖

## 本地运行

无需构建。起静态服务器（ES Module 需要 HTTP 协议）：

```bash
python -m http.server 8000
# → http://localhost:8000
```

## 部署

项目已接入 Cloudflare Pages Git 集成：推送 `main` 分支即自动构建部署（无构建步骤，输出目录为仓库根目录）。首次接入时在 Workers & Pages 创建 Pages 项目并连接 GitHub 仓库即可；也可用 Direct Upload 手动上传作为应急方式。
